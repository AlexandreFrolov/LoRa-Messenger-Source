# LoRa-2026 Chat на ESP32-S3-N16R8 — сборка и тестирование

Важная оговорка: код написан вручную, по документированному API библиотек
EByte_LoRa_E22, ESPAsyncWebServer/AsyncTCP и Arduino-core для ESP32-S3.
В этой среде нет тулчейна Xtensa/ESP-IDF и доступа к серверам Espressif,
поэтому реальной компиляции здесь не производилось — соберите и прошейте
через Arduino IDE по шагам ниже, будьте готовы поправить мелкие несовпадения
сигнатур методов под конкретные версии установленных у вас библиотек.

## 1. Структура проекта

```
lora_chat_esp32/
├── lora_chat_esp32.ino     ← основной скетч
├── partitions.csv          ← таблица разделов (большой LittleFS)
└── data/                   ← файлы веб-интерфейса, заливаются в LittleFS
    ├── index.html
    ├── style.css
    └── app.js
```

Папка должна называться так же, как .ino-файл (`lora_chat_esp32`), это
требование Arduino IDE — все имена уже совпадают.

## 2. Установка Arduino IDE и ESP32 core

1. Arduino IDE 2.x.
2. File → Preferences → Additional boards manager URLs:
   `https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json`
3. Tools → Board → Boards Manager → установить **esp32 by Espressif Systems**
   (версия 3.x — на ней проверялись сигнатуры AsyncTCP/ESPAsyncWebServer ниже).

## 3. Библиотеки (Library Manager, Ctrl+Shift+I)

| Библиотека | Автор | Примечание |
|---|---|---|
| EByte LoRa E22 | Renzo Mischianti | та же, что и в `e22_soft_repeater.ino` |
| Adafruit NeoPixel | Adafruit | для встроенного RGB на GPIO48 |
| ArduinoJson | Benoit Blanchon | v6 или v7 |
| AsyncTCP | ESP32Async (форк, актуальный для ESP32 core 3.x) | искать `AsyncTCP` от `ESP32Async` в Library Manager |
| ESPAsyncWebServer | ESP32Async (форк) | искать `ESPAsyncWebServer` от `ESP32Async` |

Если ставите не через Library Manager, а вручную с GitHub — берите форки
`ESP32Async/AsyncTCP` и `ESP32Async/ESPAsyncWebServer`, оригинальные
me-no-dev давно не обновлялись и могут не собраться на новых core.

## 4. Плагин для заливки данных в LittleFS

Arduino IDE 2.x сам не умеет заливать папку `data/` — нужен плагин
**arduino-littlefs-upload**:

1. Скачать `.vsix` последнего релиза:
   https://github.com/earlephilhower/arduino-littlefs-upload/releases
2. Положить файл в `~/.arduino15/plugins/` (Linux/Win) или
   `~/Library/Arduino15/plugins/` (macOS), создать папку, если её нет.
3. Перезапустить Arduino IDE. Появится пункт в палитре команд
   (Ctrl+Shift+P) → **"Upload LittleFS to Pico/ESP8266/ESP32"**.

## 5. Настройки платы (Tools)

| Параметр | Значение |
|---|---|
| Board | ESP32S3 Dev Module |
| USB CDC On Boot | **Disabled** (иначе `Serial.print` пропадает — см. комментарий из `e22_read_config.ino`) |
| PSRAM | OPI PSRAM |
| Flash Size | 16MB |
| Partition Scheme | Custom → указать `partitions.csv` из проекта (или через `Tools → Partition Scheme → Custom` и подложить файл рядом со скетчем — Arduino IDE подхватывает `partitions.csv` автоматически, если он лежит в папке скетча) |
| Upload Speed | 921600 (при проблемах — снизить до 460800) |

## 6. Настройка адреса узла перед каждой прошивкой

В начале `lora_chat_esp32.ino`:

```cpp
#define NODE_ADDL      0x01     // на втором узле поставить 0x02, на третьем 0x03 ...
#define NODE_NICK      "node1"
#define FLOOD_TTL      3
```

Меняйте `NODE_ADDL` на каждой прошиваемой плате — иначе узлы будут путать
свои и чужие пакеты в дедупе.

## 7. Порядок прошивки

1. Открыть `lora_chat_esp32.ino` в Arduino IDE.
2. Подключить плату, выбрать правильный COM/tty-порт.
3. Сначала залить файловую систему: Ctrl+Shift+P → *Upload LittleFS to...*
4. Затем прошить сам скетч: обычная кнопка Upload.
5. Открыть Serial Monitor на 115200 бод — должны появиться строки вида:
   ```
   === LoRa-2026 Chat (ESP32-S3-N16R8 + E22-900T22D) ===
   LittleFS OK
   AP запущена: LoRa-2026
   IP: 192.168.4.1
   Конфигурация E22: OK
   Адрес узла: 00:01, NETID: 02, канал: 19
   Готово. Подключайтесь к точке доступа...
   ```

## 8. План тестирования

### 8.1. Веб-часть отдельно (без второй LoRa-платы)
1. Телефоном/ноутбуком подключиться к Wi-Fi `LoRa-2026` (пароль `lora2026pass`).
2. Открыть `http://192.168.4.1/` — должен открыться интерфейс чата.
3. Проверить captive-portal: на Android/iOS при подключении к AP обычно сам
   выскакивает диалог "Войти в сеть" — это работа `/generate_204` и
   `/hotspot-detect.html` редиректов.
4. Отправить сообщение с одного устройства — оно должно появиться локально
   с пометкой без бейджа "LoRa" (т.к. ушло только в радиоэфир, а не
   пришло оттуда).
5. Открыть страницу на втором устройстве в той же Wi-Fi-сети — оно должно
   получить историю (`type: "history"`) и увидеть то же сообщение.
6. Отключить Wi-Fi на телефоне и снова включить — индикатор статуса должен
   переключиться офлайн → онлайн, WebSocket переподключается сам
   (см. `setTimeout(connect, 1500)` в `app.js`).

### 8.2. Радиочасть — минимум два узла
1. Прошить вторую плату с `NODE_ADDL = 0x02`.
2. У каждой платы — свой ноутбук/телефон, подключённый к её собственной AP.
3. Отправить сообщение с узла 1 → на Serial Monitor узла 2 должно появиться
   `[RX] node1: ... (RSSI ..., from=1)`, а в браузере узла 2 — сообщение
   с бейджем "LoRa".
4. Проверить RSSI в реальных условиях — значение должно совпадать по
   порядку с тем, что вы уже видели в `e22_soft_repeater.ino` на той же
   дистанции.
5. Отправить одновременно с обеих плат несколько сообщений подряд —
   проверить, что LBT (`enableLBT = LBT_ENABLED`) не даёт эфиру "давиться":
   ошибок TX по логам быть не должно, возможны небольшие задержки.

### 8.3. Флуд-ретрансляция (3+ узла)
1. Третий узел `NODE_ADDL = 0x03` разместить так, чтобы он был вне прямой
   видимости узла 1, но слышал узел 2 (как раньше — репитер посередине).
2. Отправить сообщение с узла 1: узел 2 должен и показать его у себя,
   и ретранслировать (Serial: `[REPEAT] from=1 msgId=... ttl->2 : ...`,
   вспышка LED зелёным на узле 2).
3. Узел 3 должен получить это же сообщение через ретрансляцию узла 2 и
   тоже показать в браузере с бейджем "LoRa" — без дублей (проверка
   `alreadySeen`/дедупа).
4. Понизьте `FLOOD_TTL` до 1 и повторите — сообщение не должно дойти до
   узла, находящегося за две ретрансляции.

### 8.4. Длинные сообщения (проверка разбиения на части)
1. Отправить сообщение длиннее 38 символов (например, 150 символов).
2. На Serial Monitor отправителя должны быть строки
   `[TX] chunk 1/4 OK`, `[TX] chunk 2/4 OK` и т.д.
3. На принимающей стороне — `[RX-ASSEMBLED] ...` с полностью собранным
   текстом, и только одно сообщение в браузере (не 4 отдельных).

### 8.5. Нагрузочная проверка
1. Открыть 3-4 вкладки браузера одновременно к одному узлу.
2. Слать сообщения из разных вкладок — все должны получать всё без
   задержек, свойственных зависанию `loop()` (WebSocket не блокируется
   ожиданием LoRa, т.к. приём/передача радио вынесены в отдельную
   FreeRTOS-задачу на ядре 0, см. `loraTask`).

## 9. Известные места, которые стоит перепроверить под вашу версию библиотек

- `e22.receiveMessageRSSI(size_t)` — в некоторых версиях библиотеки метод
  принимает длину ожидаемого пакета, в других читает "как есть" до конца
  посылки. Если у вас другая сигнатура — уберите аргумент и проверяйте
  `rc.data.length() == sizeof(ChatPacket)` как в коде.
- `e22.sendFixedMessage(ADDH, ADDL, CHAN, uint8_t*, size_t)` — бинарный
  оверлоад есть не во всех версиях библиотеки; если его нет у вас,
  замените на `String` вариант, обернув `ChatPacket` в `String` через
  побайтовое копирование, либо обновите библиотеку до последней версии
  с GitHub Рензо Мисчианти.
- Широковещательный адрес `0xFFFF` у EBYTE документирован как "приём всеми
  модулями сети независимо от их собственного адреса" — обязательно
  проверьте это по факту на своих модулях (иногда прошивки конкретной
  партии ведут себя чуть иначе); если не сработает — временно замените
  на явную адресацию по списку известных узлов, как в
  `e22_soft_repeater.ino`.
- Лимит полезной нагрузки 53 байта (see `ChatPacket`) подобран с запасом
  под типичные ограничения fixed-режима E22, но зависит от вашей
  конфигурации SF/BW — если модуль будет ругаться на длину, уменьшите
  `TEXT_CHUNK_LEN`.
